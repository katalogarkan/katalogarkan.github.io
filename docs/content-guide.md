## 1. Overview

This website uses **Astro Content Collections** to manage content. This means you don't need to touch HTML/Astro files to add a new project or article. Simply create a Markdown (`.md`) file, and Astro will automatically render its page.

There are two main collections:
1. **Katalog** (`src/content/katalog/`) — For displaying portfolio projects.
2. **Blog** (`src/content/blog/`) — For writing technical articles or notes.

---

## 2. File Naming & Routing Rules

- **Format:** All files must end with `.md`.
- **Slug (URL):** The file name becomes the detail page URL.
  - Example: `batchetl-pipeline.md` becomes `/katalog/batchetl-pipeline`.
- **Naming Rules:** Use all lowercase letters and connect words with hyphens (`-`). Do not use spaces or underscores (`_`).

## 3. Katalog (Portfolio Projects)

Folder: `src/content/katalog/`

### 3.1 Frontmatter Schema (Required)
Every Katalog file must start with the following YAML format:

```yaml
---
title: "Project Title"
description: "A short 1-2 sentence summary of the project."
techStack: ["Python", "Apache Airflow", "PostgreSQL"]
thumbnail: "/images/projects/project-name/thumbnail.png"
demoUrl: "https://link-to-demo.com"
repoUrl: "https://github.com/ArkanTsabit123/repo-name"
category: "data-engineering" 
featured: true
date: 2025-09-15
---
```

### 3.2 Frontmatter Value Rules
- **`category`:** Must be one of: `web-app`, `data-engineering`, or `cloud-devops`.
- **`demoUrl` & `repoUrl`:** Optional. If not available, **delete the line** (do not leave it empty as `""`), or Astro will error.
- **`featured`:** Set to `true` if you want the project to appear on the Home page, `false` if not.
- **`date`:** Format `YYYY-MM-DD`.

### 3.3 Body Structure (Markdown)
After the `---`, you can write regular Markdown. It is highly recommended to use the **Problem → Solution → Impact** structure:

```markdown
## Executive Summary
(Opening paragraph)

## The Problem
(The client's business problem)

## The Solution
(Technical solution and architecture)
![Architecture Diagram](/images/projects/project-name/architecture.png)

## The Results
- 2.96M+ rows processed.
- 100% data quality.
```

## 4. Blog (Articles)

Folder: `src/content/blog/`

### 4.1 Frontmatter Schema (Required)

```yaml
---
title: "Article Title"
date: 2025-10-28
description: "A short summary for SEO and card preview."
category: "tutorial"
tags: ["airflow", "python", "data-engineering"]
draft: false
coverImage: "/images/blog/article-name/cover.jpg"
---
```

### 4.2 Frontmatter Value Rules
- **`category`:** Must be one of: `tutorial`, `tips`, or `notes`.
- **`draft`:** Set to `true` if the article is unfinished (it will not appear on the website). Change to `false` when ready to publish.
- **`coverImage`:** Optional. If not available, delete the line.

### 4.3 Body Writing Rules
- **Do not use H1 (`#`)** inside the article body. The H1 title is automatically generated by the layout from the `title` in the frontmatter.
- Use `##` for subheadings and `###` for sub-subheadings.
- Use code blocks (```` ``` ````) with the language name (e.g., ```` ```python ````) so the syntax highlighting is neat.

## 5. Images & Assets

- **Location:** All images are stored inside the `public/` folder (not `src/`).
- **Path:** Reference images with a leading slash `/`.
  - Example: Save at `public/images/projects/batchetl/dashboard.png`.
  - Reference in Markdown: `![Dashboard](/images/projects/batchetl/dashboard.png)`.
- **Recommended Sizes:**
  - Katalog Thumbnail: 1200x675px (16:9).
  - Blog Cover: 1200x630px.

---

## 6. Publishing Workflow

1. **Create/Edit the file** in the appropriate folder (`katalog/` or `blog/`).
2. **Add images** to the `public/images/` folder if needed.
3. **Test Locally:** Run `npm run dev` and open the corresponding page.
4. **Validate:** Run `npm run build`. If you see a red error, your YAML format is incorrect.
5. **Commit & Deploy:**
   ```bash
   git add .
   git commit -m "content: add new article about airflow"
   git push origin main
   ```
6. The website will automatically update within 1–2 minutes.
